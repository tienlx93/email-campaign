Agent implementation notes

  • Route: /settings — protected, under AuthenticatedLayout
  • Two independent forms: Profile (name only) and Change Password — each with its own submit button and success/error toast
  • Email: read-only field, not editable (per spec)
  • Avatar: shown at top of card using same 2-initial + color logic as top bar; updates live when name is saved
  • Name form: Zod schema — name required, min 1 char, max 100; on success dispatches updated user to authSlice so top bar avatar/name update immediately
  • Password form: Zod schema — currentPassword required, newPassword min 8 chars, confirmPassword must match newPassword; client validates match before submit
  • Backend — PATCH /auth/profile: accepts optional name field; returns updated user object; follow TDD
  • Backend — PATCH /auth/password: accepts currentPassword + newPassword; verifies current password with bcrypt, hashes and saves new; returns 200 on success, 401 if current password wrong; follow TDD
  • Toasts: success ("Name updated") and error messages via existing Sonner toast
